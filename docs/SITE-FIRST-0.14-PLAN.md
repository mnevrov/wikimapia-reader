# WikiReader Next 0.14.0 — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** реальные данные Wikimapia без обязательного ключа, с приоритетом сайта и дополнением через API при наличии личного ключа.

**Architecture:** адаптеры сайта и API возвращают нормализованные данные и статусы отдельных блоков. Маршрутизатор выбирает сайт первым, API — только для неподтверждённых блоков. Android-транспорт изолирован от WebView приложения; текущие модели карточек и офлайн-хранилище сохраняются.

**Tech Stack:** React 19, Capacitor 8, Java Android, Node test runner, Playwright, Gradle/JUnit; парсинг HTML через DOMParser в JS без выполнения исходных скриптов.

**Spec:** `docs/SITE-FIRST-0.14-DESIGN.md`.

## Global Constraints

- Никаких чужих ключей, сторонних прокси и замены HTTPS на HTTP.
- Личный API-ключ остаётся в существующем Android Keystore; страницы и фото не получают его.
- Существующий интервал REST — не менее 6 секунд.
- Без ключа на Android работают реальные контуры, карточки, фотографии и комментарии.
- Поиск сайта проверен либо ограничение явно согласовано перед выпуском.
- Не обходить CAPTCHA, запреты доступа и rate limit; остановиться с понятным статусом.
- Сохранить избранное, историю, офлайн-чтение, темы, GPS Follow и верхние ошибки 0.13.2.
- Выпуск 0.14.0/versionCode 28 допустим только после повторной проверки актуального main.
- Подписанный APK публикуется существующим workflow с прежним сертификатом Next.

## Review Focus

1. HTTP 200 с cookie-оболочкой или RK n.22 не становится пустой успешной карточкой — задачи 1, 2, 4.
2. Смена/удаление ключа во время запроса не возвращает устаревшую карточку и не теряет локальные данные — задачи 4, 5.
3. Дочерние тайлы, пустые страницы и повреждённая геометрия не доказывают полное покрытие — задача 3.
4. Комментарий без даты и неизвестный HTML-блок не превращаются в вымышленные даты/пустые данные — задача 2.
5. Внешний редирект, вредоносный HTML или URL фото не исполняется и не получает ключ — задачи 1, 2.

## Карта файлов

- `src/siteTransport.js` и Android `WikiReaderSitePlugin.java`: ограниченные HTTPS-запросы сайта, сессия, отмена, лимиты.
- `src/siteHtml.js`: чистое преобразование HTML в карточки/результаты поиска.
- `src/siteTiles.js`: адреса тайлов, декодирование, ограниченная загрузка и покрытие.
- `src/dataSource.js`: выбор источника, дополнение недоступных блоков, единые результаты.
- `src/client.js`, `src/api.js`: сохранить REST-транспорт; добавить выбор data_blocks для резервных запросов.
- `src/main.jsx`, `MapPane.jsx`, `Settings.jsx`, `Details.jsx`, `area.js`, `areaCache.js`: подключение, статусы и реальный режим без ключа.
- `tests/site*.test.mjs`, `tests/dataSource.test.mjs`, Android/JUnit и `tests/browser/siteFirst014.spec.js`: проверки новых контрактов.
- `docs/DATA-SOURCES.md`, `README.md`, `docs/releases/0.14.0/RELEASE_NOTES.md`: новая модель доступа и подтверждённые ограничения.

### Задача 1. Проверяемый транспорт сайта на Android

**Interfaces:** `siteRequest({url, signal, headers}) -> Promise<{status, text, headers, finalUrl}>`; только HTTPS wikimapia.org для текста. Не возвращать cookies в JS или диагностике. Предельный распакованный ответ 4 МиБ, тайм-аут 12 секунд, не более двух одновременных запросов. Редиректы проверяются до перехода.

- [ ] Написать тесты отказа для http, URL с credentials, стороннего домена/редиректа, 403/429, превышения размера, отмены до/после ответа и cookie-оболочки; они должны падать до реализации.
- [ ] Реализовать Android-плагин и JS-обёртку; зарегистрировать в `MainActivity.java`. Сессию держать отдельно от ключа. Не исполнять произвольный JS страницы.
- [ ] Проверить обычное получение полноценной карточки на Android. Если требуется взаимодействие пользователя, показать отдельный официальный WebView без моста приложения. Не объявлять парсинг работающим на основании WebView.
- [ ] Проверить контракт поиска сайта по актуальному form/action из `application.js` и полученному HTML, записать только несекретный результат; отсутствие подтверждения — блокер полного поиска без ключа.
- [ ] Запустить новые unit/JUnit проверки и зафиксировать результат отдельным коммитом.

### Задача 2. Парсинг карточек, фотографий, комментариев и поиска

**Interfaces:** `parseSitePlace(html, expectedId) -> {place, blocks}`; `place` совместим с `normalizePlace`: `{id,title,description,url,photos:[{src,author}],comments:[{author,text,date}]}`. `blocks` хранит `ok|empty|unavailable|invalid` для title/description/photos/comments. `parseSiteSearch(html) -> {places, complete}` возвращает существующие объекты области `{id,title,coords,url}`; отсутствие контура допустимо для результатов поиска.

- [ ] Добавить минимальные обезличенные фикстуры структуры реальной карточки №350, скрытых комментариев, галереи и частичной карточки №339; не публиковать чужие полные тексты/комментарии и cookies. Проверить утверждения в живой странице отдельно.
- [ ] Написать падающие тесты: 5 видимых + 11 скрытых комментариев дают 16 записей; дубликаты не удваиваются; неизвестная дата даёт null; RK n.22 даёт недоступный блок; неожиданный ID отклоняется; отсутствующий узел не считается достоверно пустым.
- [ ] Реализовать HTML-парсер: DOMParser, извлечение текста без script/style/рекламы, нормализация переносов, ID комментариев внутри адаптера, allowlist HTTPS-адресов фотографий. `a.thumb-link` читается без запуска галереи сайта.
- [ ] Проверить XSS-фикстуры и вредоносные URL, альтернативные языки, пустую галерею/комментарии с подтверждённой структурой. Парсер не генерирует даты из «N лет назад».
- [ ] Прогнать тесты HTML в браузере, где доступен DOMParser; чистые правила — Node. Сохранить коммит парсера.

### Задача 3. Контуры сайта и честная полнота покрытия

**Interfaces:** `tileAddress(x,y,z) -> {id,url}`; `parseSiteTile(text, expectedId) -> {places,deeperTiles}`; `loadSiteArea({bbox,signal}) -> {places,complete,source:'site'}`. Геометрия нормализована в `[lat,lon]`.

- [ ] Написать падающие тесты рассчитанного quadkey, масштаба bbox 1e7, обеих кодировок, границ долготы/широты, усечённого varint, неверного заголовка, повторного ID, пустого дочернего тайла и отмены.
- [ ] Реализовать адреса и декодер по проверенному формату; ограничить глубину z=15, длину записи, количество точек и тайлов одного задания (не более 16). Превышение бюджета возвращает `complete:false`, а не ложное полное покрытие.
- [ ] Реализовать дедупликацию очереди и ограниченный кэш 32 тайлов/8 МиБ. Условные запросы включать только после отдельной проверки 304 и повторного использования тела; иначе использовать TTL 5 минут.
- [ ] Изменить `AreaLoader` для явного `complete` источника: неизвестное `found` и менее 50 объектов не доказывают полноту тайлов. Добавить `source` и версию формата в сохраняемый кэш, сохранив чтение старых записей.
- [ ] Прогнать `node --test tests/siteTiles.test.mjs tests/area.test.mjs tests/areaCache.test.mjs` и зафиксировать коммит.

### Задача 4. Гибридная маршрутизация без лишней квоты

**Interfaces:** `createDataSource({site, api, getKey}) -> {getPlace(id,{signal}), getArea(opts), search(opts)}`. Зависимости инъецируются, ключ читается при выполнении. Результат содержит данные, источник и предупреждения по блокам.

- [ ] Написать падающие тесты: без ключа API не вызывается; полный сайт с ключом не вызывает API; частичное описание запрашивает только нужный data_block; сбой API сохраняет успешные фото/комментарии сайта; отмена не запускает fallback.
- [ ] Реализовать дополнение по блокам и дедупликацию. Не смешивать списки без устойчивых ID, не затирать успешный сайт пустым API. Явная ошибка ограничения сайта не вызывает повторный запрос к тому же маршруту.
- [ ] Дополнить `buildRequest` безопасным allowlist для data_blocks; REST по умолчанию сохраняет текущий контракт. Отдельные тесты: ключ только в api.wikimapia.org, прежний интервал, ключ не попадает в ошибки.
- [ ] Добавить тест смены ключа/отмены в полёте и отказа парсера, который ранее мог возвращать пустой успех. Прогнать весь Node-набор и зафиксировать коммит.

### Задача 5. Реальный режим без ключа и интерфейс

- [ ] Написать падающие browser-тесты первого запуска без ключа, выбора контура, ID/ссылки, поиска, добавления/удаления ключа, возврата из демо и частичной карточки.
- [ ] Изменить `main.jsx`: убрать неявный demo по `!credentials.key`, разрешить карточки/кэш без ключа, сохранить отмену и офлайн-fallback. Не подменять онлайн-запрос старой офлайн-копией только из-за отсутствия ключа.
- [ ] Подключить новый источник в `MapPane.jsx`; убрать проверки `!apiKey`, сохранив active/paused/moving и бюджет загрузки. Показать источник и неполноту, не маркировать частичную область пустой.
- [ ] Изменить настройки: «API-ключ Wikimapia — необязательно», резервное дополнение и удаление без потери доступа. Предупреждения отдельных блоков — внутри карточки; ошибки карты — в существующей верхней области.

## Самопроверка плана

Каждый раздел spec покрыт задачами 1–6. Неизвестные контракт поиска и нативная сессия
вынесены в явные проверки готовности, а не скрыты за браузерными mock-тестами.
Зависимости последовательны: транспорт → парсеры/тайлы → маршрутизатор → UI → выпуск.
Новые функции получают тесты до реализации. Задача 6 включает независимое ревью,
но не требует параллельной разработки одних и тех же файлов.
