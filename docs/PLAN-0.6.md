# WikiReader Next 0.6 — план реализации

Цель: карта остаётся читаемой и спокойной при навигации, использует общий кэш
покрытия и позволяет управлять сохранёнными областями. Все пять изменений
одобрены пользователем; выполнение автономное, последовательно, с независимым ревью.

## Поведение

1. Если контуры уже доступны, обновление/догрузка отображаются только анимацией
   кнопки обновления. Надпись загрузки допустима лишь для первого запроса без данных.
   Отмена, пауза и переходы не оставляют ложный статус загрузки.
2. Полное покрытие видимой области объединением свежих **полностью загруженных**
   bbox обходится без запроса. Наличие зазора или недогруженных страниц не считается
   полным покрытием. Одна частичная запись сохраняет собственную пагинацию.
3. Обычные полигоны: контур 1.5 px, без заливки. Выбранный объект: янтарный контур,
   заливка 0.12. При нажатии проверяются внутренность и близость к границе (8 px).
   Несколько совпадений открывают список, маленькие объекты идут первыми.
4. Настройки показывают размер сериализованных контуров, число областей,
   закрепления, даты обновления, переход на карту. Срок обычного кэша: 1/7/30 дней,
   по умолчанию 1 день. Свежесть для сети остаётся 5 минут при обращении к области.
5. Закрепление запрещает автоматическое удаление по сроку/лимиту. 32 области и
   12 МиБ остаются общим пределом. Переполнение при закреплении сообщает об ошибке;
   обновление закреплённой записи не снимает закрепление. Обычная очистка сохраняет
   закреплённые записи, удаление всех требует отдельного явного действия.

Никаких новых источников данных, тайлов Wikimapia, прокси или увеличения частоты
API. Ключ не попадает в кэш. Подложка и карточки пока не сохраняются офлайн.

## Риски для ревью

- Объединённое покрытие не теряет сведения о незавершённых страницах.
- Переключение экрана/ключа/очистка отвергают запоздалые ответы и чтения кэша.
- Лимит не вытесняет закреплённые записи, сетевое обновление сохраняет pin.
- Выбор на карте не срабатывает после drag и не открывает случайный крупный полигон.
- Старый IndexedDB v1 обновляется без потери записей; ошибка диска не блокирует API.

Физическое устройство остаётся отдельной проверкой: успешные mock-тесты её не заменяют.
