# Выпуск APK через GitHub Actions

Каждая новая версия публикуется в GitHub Releases автоматически по тегу vX.Y.Z.
Вход агента в веб-интерфейс для каждого выпуска больше не требуется.
Публикацию выполняет временный GITHUB_TOKEN внутри Actions; личный PAT не нужен.

## Однократная настройка владельцем репозитория

Откройте Settings → Secrets and variables → Actions → New repository secret.
Добавьте три секрета:

| Имя | Значение |
| --- | --- |
| NEXT_KEYSTORE_BASE64 | Прежний файл wikireader-next-development.jks, закодированный base64 одной строкой |
| NEXT_STORE_PASSWORD | Пароль хранилища из приватной резервной копии подписи |
| NEXT_KEY_PASSWORD | Пароль ключа wikireader-next из той же резервной копии |

Используйте существующую резервную копию Next, переданную в чате. Новый ключ
создавать нельзя: подпись перестанет совпадать, и обновление поверх установленного
приложения не получится. JKS/base64/пароли не вставлять в код, issue, комментарии
или логи. Закрытый ключ остаётся только в приватной копии и GitHub Secrets.
Локально base64 можно получить командой `base64 -w 0 wikireader-next-development.jks`;
вводите результат непосредственно в поле Secret. Не публикуйте его в чате.

Workflow сверяет сертификат с известным SHA256 Next:
`f2e7ecb97e30017f5fb43f59650c1a14b001a328b440d435f81751dd97900bba`.
Отсутствие секретов или другой сертификат останавливают выпуск.

## Каждая итерация с новой версией

1. Обновить package.json/package-lock.json, Android versionName и versionCode.
2. Подготовить docs/releases/X.Y.Z/RELEASE_NOTES.md: изменения, установка поверх
   предыдущей версии, реальные результаты проверок и непроверенные сценарии.
3. Провести ревью и объединить изменения в main. Тег должен указывать на коммит,
   входящий в main; workflow проверяет это перед подписанием.
4. В Actions → Android APK → Run workflow выбрать main и указать release_tag,
   например v0.7.3. Workflow создаст тег на проверенном коммите при публикации.
   Альтернатива — создать и отправить тег из терминала:

   ```bash
   git tag v0.7.3
   git push origin v0.7.3
   ```

5. Дождаться успешного workflow Android APK. Для тега он дополнительно создаёт
   WikiReader-Next-X.Y.Z.apk и SHA256SUMS.txt, проверяет сертификат/package/версию
   и соответствие assets исходной сборке.
6. Job publish создаёт черновик GitHub Release, загружает APK и SHA256SUMS.txt,
   скачивает оба файла обратно, сверяет контрольную сумму и только затем
   публикует релиз. Приватный репозиторий требует входа и доступа для скачивания.
7. Убедиться в наличии опубликованного релиза и дать пользователю ссылку на него
   и APK. Для повтора сбоя публикации используйте Re-run failed jobs в том же tag
   workflow: publish получит исходный подписанный артефакт, без пересборки APK.

Опубликованный релиз workflow не перезаписывает: при повторе сверяет его файлы
с результатом сборки. Незавершённый черновик можно дозаполнить и опубликовать.
Если APK при пересборке отличается, автоматическая перезапись опубликованного
релиза запрещена: требуется новая версия либо явное разбирательство владельца.

## Что именно выпускается

Это совместимая сборка WikiReader Next с package org.example.wikimapreader.next,
подписанная постоянным сертификатом. Сохраняется существующий debug build variant;
GitHub Release не превращает её в production-вариант Android или выпуск Google Play.
Обычные branch/PR сборки остаются временными неподписанными постоянным ключом
артефактами Actions. Job публикации имеет contents:write, сборка — contents:read;
секреты используются только при выпуске по тегу или ручном запуске с release_tag. Файл ключа удаляется после подписания.

## Подтверждённые проверки автоматизации

Локально проверены синтаксис shell/YAML, реальное подписание APK 0.7.3 прежним
ключом, сертификат/package/version/assets, отказ для другого тега и без секрета.
Четыре offline-теста публикации с mock gh проверяют порядок download→publish,
неизменность опубликованного релиза, отказ при повреждённом скачивании
и отклонение тега, указывающего на другой коммит.
Сквозная публикация подтверждена 18.10.2026: [Actions #38](https://github.com/mnevrov/wikimapia-reader/actions/runs/39153258482)
завершился успешно и опубликовал [v0.7.3](https://github.com/mnevrov/wikimapia-reader/releases/tag/v0.7.3).
65 Node, 7 Python и 69 браузерных тестов прошли; Gradle testDebugUnitTest,
assembleDebug и lintDebug — PASS. Job publish скачал APK и SHA256SUMS.txt
обратно из черновика и проверил сумму до публикации. Страница Releases
подтверждает Latest, тег на b1d04ae и оба вложения. SHA256 APK совпадает
с ранее проверенным локальным APK. Дополнительное скачивание через облачный
браузер не завершилось из-за ограничения его среды; это не проверка скачивания
на телефоне. Физический Android, FPS и TalkBack остаются NOT_RUN.
Первый запуск #36 остановился из-за отсутствия rg в runner; зависимость заменена
на Python, исправление проверено успешным запуском #38.
