# WikiReader Next 0.15.5 — поддержка родительских тайлов Wikimapia

## Обнаруженная несовместимость
Диагностика на физическом Android 16 в версии 0.15.4 показала: `site.tiles.total=4`, `success=4`, `tileParseReasons.header=4`, `manualRefresh.started=1`. Код парсера требовал строгое совпадение ID ответа и запрошенного тайла. Независимый декодер NaKarte умеет принимать ID фактически возвращённого тайла, который может быть родительским, и пропускает служебную строку границ после заголовка. Это сильное объяснение наблюдаемого сбоя, но без тела ответов с телефона не подтверждает единственную возможную причину.

## Исправлено
- Поддержан ответ родительского тайла: принимается только валидный quadkey, являющийся префиксом ID запрошенного тайла. Ответ с несовпадающей областью по-прежнему отвергается.
- Заголовок родителя не считается полной детализированной областью; валидные контуры отображаются с честным статусом неполного покрытия.
- Учитывается необязательная служебная строка границ `west|east|south|north` между заголовком и строками объектов; ошибочные строки объектов не скрываются под этим правилом.
- Исправлены обе реализации декодирования: мобильная React/Capacitor и Android Auto Java.
- Добавлен безопасный счётчик `tileDecode.parent` и повышена схема отчёта до 4; координаты, ключи, URL и содержимое геоданных не записываются.
- Регрессионные Node и Android/JUnit тесты проверяют принятие родительского тайла, отклонение чужого соседнего тайла и обработку метаданных границ.

## Установка
- Единый APK для телефона и Android Auto: `org.example.wikimapreader.next`, `versionName 0.15.5`, `versionCode 40`.
- Обычный GitHub Release без Beta. Штатный релизный workflow должен проверить CI, подписать APK прежним сертификатом и сверить checksum опубликованного файла.
- Устанавливается поверх официальной 0.15.4; пользовательские данные при обычном обновлении сохраняются.

## Проверка и ограничения
- Node/Python, Playwright, Gradle JVM unit/lint/assemble, живой публичный тайл через Android emulator и подпись APK проверяются CI до выпуска. Результат физического Honor V2 / Android 16 пока не подтверждён.
- Если сервер возвращает невалидный заголовок (непредковый ID, некорректный формат) или ограничение доступа, тайл не подменяется вымышленными объектами. В таком случае требуется дальнейшая диагностика ответа, а не отключение проверки.
- Аппаратные сценарии Android Auto остаются непроверенными на конкретном автомобиле и не считаются принятыми.
