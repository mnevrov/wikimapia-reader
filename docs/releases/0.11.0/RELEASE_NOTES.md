# WikiReader Next 0.11.0 — устойчивость API и понятные статусы

## Что изменилось
- Классификация сбоев Wikimapia API на offline, auth, quota, schema, timeout, network и другие безопасные категории. Приложение не выводит сырые ответы сервера или API-ключ в диагностике.
- При загрузке контуров на карте ошибки авторизации, квоты и формата ответа не запускают бездумных повторных запросов.
- В панели «Объекты в области» отображается свежесть и неполнота данных кэша.
- Добавлены тесты на ошибочные ответы Wikimapia при HTTP 200, повреждённый JSON, HTTP 401/429 и возраст кэша.
- Интервал между запросами API не менее 6 секунд, HTTPS и существующий метод box сохранены, недокументированные альтернативы и сторонние proxy не используются.
- Обновления не меняют формат пользовательского избранного и сохранённого офлайн-чтения.

## Обновление
Установите WikiReader-Next-0.11.0.apk из GitHub Release поверх WikiReader Next 0.10.0. Идентификатор приложения org.example.wikimapreader.next и постоянный сертификат Next должны совпадать; релизный workflow проверяет их перед публикацией. Проверьте SHA256SUMS.txt.

## Проверки и ограничения
- PR CI на исходном коммите df99327 прошёл GitHub Actions; после изменения номера версии требуется новый успешный CI и релизная проверка.
- Инструментальные замеры GPS, энергопотребления, живого API с личным ключом и smoke-test на физическом Android не выполнены. Browser mock не заменяет проверку устройства.
- Метод box всё ещё устаревающий; автоматическое переключение на place.getbyarea пока не разрешено без подтверждения его контракта на живом API.
- Метрики задержки/покрытия, расширенная диагностическая история и отдельная классификация состояния поиска остаются дальнейшими задачами #16, если это потребуется.
