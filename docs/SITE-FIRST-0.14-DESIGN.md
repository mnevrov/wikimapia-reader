# WikiReader Next 0.14.0: ключ Wikimapia необязателен

Статус: проект решения для проверки перед реализацией. База: main 86a7db5, версия 0.13.2.

## Цель

Приложение открывает реальные объекты без обязательного API-ключа. Сайт —
приоритетный источник. Добавленный личный ключ дополняет недоступные либо
недостоверно разобранные данные. Удаление ключа не включает демонстрацию и не
закрывает доступ к карте, избранному и офлайн-копиям.

## Выбранный подход

Отдельные адаптеры сайта и REST за общим маршрутизатором. Существующий REST-клиент,
его HTTPS, интервал 6 секунд и защищённое хранение ключа сохраняются.
Полная замена интерфейса официальным сайтом не подходит: она теряет собственные
карточки и офлайн-чтение. Простой fallback только при отсутствии ключа не подходит:
пользователь требует приоритет сайта и при наличии ключа.

| Операция | Сначала | При сбое с ключом | При сбое без ключа |
| --- | --- | --- | --- |
| Объекты области | Прямые itiles Wikimapia | REST box | Кэш и сообщение об ошибке |
| Описание | Публичная HTML-карточка | REST place.getbyid | Доступные блоки и ссылка на оригинал |
| Фотографии | Метаданные галереи HTML и HTTPS photos.wikimapia.org | Блок photos API | Доступные фотографии и явный статус |
| Комментарии | HTML, включая скрытый блок | Блок comments API | Доступные комментарии и явный статус |
| Поиск по названию | Поиск официального сайта после проверки контракта | REST search | Ошибка поиска; ID/ссылки и локальный поиск остаются доступны |
| ID / ссылка | HTML-карточка | REST place.getbyid | Ошибка конкретной карточки |

Если контракт поиска сайта не удаётся подтвердить, выпуск не должен заявлять
полный поиск без ключа: это отдельный критерий готовности, а не молчаливая замена
глобального поиска поиском по текущей области.

## Достоверность и объединение

Для каждого блока различаются: успешно получен, достоверно пуст, недоступен,
структура неизвестна. Пустой массив после неудачного парсинга не означает отсутствия
фото/комментариев. Ошибки RK n.22, оболочка установки cookie, страница ошибки и
HTML с неожиданным ID не считаются полноценной карточкой.

Успешные блоки сайта сохраняются; API запрашивается только для недоступных блоков.
Фото объединяются по ID/каноническому URL, комментарии — по ID. При отсутствии
стабильных ID смешивание списков запрещено: используется один проверенный блок.
Неизвестные даты не превращаются в текущую дату. Источник и частичная загрузка
видны пользователю. Ошибка API не уничтожает уже полученные блоки сайта.

## Транспорт Android

Нативный HTTPS-транспорт обязателен для проверки: браузерные результаты не
подтверждают CapacitorHttp/CORS. Обычная сессия сайта может требовать cookie nsess.
Не исполнять HTML или произвольные скрипты внутри основного origin приложения.
Не переносить API-ключ в запросы к страницам, фото или сторонним доменам.
Редиректы и адреса ресурсов проверяются по allowlist. Не обходить CAPTCHA,
запреты доступа и rate limit; остановиться с понятным статусом.

Если автоматический нативный транспорт не получает полноценную страницу,
официальная страница в изолированном WebView остаётся пользовательским способом
чтения. Сам по себе такой fallback не доказывает выполнение нативного парсинга.

## Тайлы, кэш и нагрузка

Декодер проверяет заголовок tile ID, обе кодировки геометрии, диапазоны координат,
ограничения длины и числа вершин. Повторяющиеся ID дедуплицируются. Признак
дочерних тайлов учитывается: неполное покрытие не маркируется полным.
Загружаются только нужные видимой области тайлы, без массовой предзагрузки.
Ограничиваются очередь, параллелизм, размер ответа и глубина детализации.

Кэш имеет источник/версию формата и признак полноты. Не смешивать полноту REST
и тайлов без доказанного покрытия. Использовать ETag/Last-Modified, если сервер
подтверждает условные запросы. Смена ключа отменяет устаревшие запросы; удаление
ключа не удаляет избранное, историю и сохранённые карточки.

## Интерфейс

Первый запуск сразу открывает реальную карту. Деморежим включается только явно.
В настройках: «API-ключ Wikimapia — необязательно» и объяснение резервного доступа.
Ошибка сайта без ключа не отправляет принудительно в настройки.
Поиск, открытие ID, сохранённые области и возврат из демо не зависят от наличия ключа.
Уведомления используют существующую верхнюю область ошибок версии 0.13.2.

## Проверки и выпуск

1. Тесты парсинга реальных обезличенных HTML/тайлов, пустых и повреждённых ответов.
2. Маршрутизация: без ключа ни одного API-запроса; полный ответ сайта не вызывает
   API даже с ключом; частичный ответ дополняется без потери успешных блоков.
3. Отмена, тайм-аут, 403/429, cookie-оболочка, RK n.22, редиректы и очистка ключа.
4. Браузерные сценарии первого запуска, настроек, областей, карточек, поиска,
   избранного, истории, офлайн-чтения, тем и GPS Follow.
5. Воспроизводимая проверка нативного Android-транспорта без личного ключа;
   отдельно обозначить отсутствие теста на физическом телефоне, если его нет.
6. Полные Node/Python/browser тесты, Gradle unit tests, assembleDebug и lintDebug,
   независимое ревью по AGENTS.md.
7. Согласовать package.json/package-lock.json и Android versionName 0.14.0,
   versionCode 28, если к моменту выпуска main не продвинулся дальше.
8. После прохождения критериев объединить релизную ветку и использовать существующий
   release workflow. Сверить прежний сертификат Next, APK и SHA256SUMS после
   публикации; дать пользователю реальные ссылки на Release и APK.

## Критерий готовности

Без ключа на Android работают реальные контуры, карточки, фотографии и комментарии;
поиск сайта проверен либо ограничение явно согласовано перед выпуском. С ключом
надёжные блоки сайта не тратят API-квоту. Основные существующие сценарии сохранены.
Подписанный APK опубликован и проверен. До этого выпуск не объявляется готовым.
