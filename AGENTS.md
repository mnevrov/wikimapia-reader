# Инструкции для разработки WikiReader

## Обязательный выпуск каждой новой версии

Это постоянное требование пользователя: каждая итерация, в которой выпускается
новая версия приложения, завершается публикацией полноценного GitHub Release
в репозитории mnevrov/wikimapia-reader. Передача APK только в чате или временного
артефакта Actions не заменяет релиз.

1. Согласовать package.json/package-lock.json, Android versionName и versionCode.
2. Выполнить подходящие тесты, независимое ревью и Android CI. Фиксировать реальные
   результаты; не выдавать браузерные mock-проверки за проверку устройства.
3. Подготовить APK с прежним сертификатом WikiReader Next, чтобы обновление
   устанавливалось поверх предыдущей версии. Проверить подпись, package/version
   и соответствие содержимого проверенной сборке. Не публиковать временно
   подписанный runner APK как совместимое обновление. Закрытый ключ не коммитить.
4. Использовать workflow Android APK и инструкции docs/RELEASING.md.
   Создать тег v<version>, указывающий на выпущенный коммит, и опубликовать GitHub
   Release с названием версии, изменениями, инструкцией по обновлению,
   подтверждёнными проверками и известными ограничениями.
5. Прикрепить WikiReader-Next-<version>.apk и SHA256SUMS.txt. Проверить доступность
   вложений и контрольную сумму опубликованного APK. Для приватного репозитория
   явно учитывать необходимость входа в GitHub и доступа к репозиторию.
6. В финальном ответе дать страницу релиза и прямую ссылку на APK. Резервная
   ссылка из чата допустима дополнительно.

Не объявлять выпуск завершённым, пока релиз и APK не опубликованы и не проверены.
При блокировке доступа назвать конкретный блокер и состояние публикации;
не придумывать ссылки и не подменять release ссылкой на Actions. Продолжать всю
доступную подготовку. Использовать разрешённые инструменты и соблюдать требования
подтверждения перехода к браузеру, если коннектор не поддерживает операцию.

Правило относится и к ближайшему выпуску 0.7.3: его GitHub Release ещё требуется
опубликовать; наличие протестированного APK и объединённого PR этого не заменяет.
После публикации удалить только это временное примечание, сохранив правило.
